A single response is a snapshot. A conversation is a sequence of decisions, updates, and consequences. Evaluating only the final sentence can hide the path that produced it.

That distinction matters whenever an AI system works across turns: helping someone complete a task, sustaining a role-play, or coordinating a multi-step plan. The system has to carry context forward, notice when circumstances change, and recognize when continuing is no longer the right move.

01 THE QUESTION

Change the unit, change the question.

Response-level evaluation asks whether an answer is relevant, clear, or safe in isolation. Those are useful properties, but they leave out the interaction state around the answer.

A process-oriented view asks what changed between turns. Did the user’s goal become more specific? Did the assistant use the new information? Did the plan make progress? Did either participant signal that the exchange should stop?

“

The object of evaluation is not a sequence of good-sounding sentences. It is a sequence whose state changes can be explained.

This reframing does not make answer quality irrelevant. It places each answer inside the work it is meant to do.

02 THE SHAPE

Progress is rarely a straight line.

Real interactions contain pauses, corrections, and reversals. A user may reveal a constraint late. An assistant may repeat a question, misread a signal, or recover after a weak turn. If we collapse this sequence into one end-state score, the route disappears.

Keeping the route visible lets a reviewer distinguish a temporary detour from a persistent stall. It also makes recovery observable: a system that notices and corrects a mistake should look different from one that repeats it until the user gives up.

Read the transition, not just the destination.

For each turn, connect the conversational evidence to the state update it supports. When the evidence is ambiguous, preserve that uncertainty.

03 THE SIGNALS

Four questions make the trace inspectable.

A practical process record can organize evidence around four complementary questions. Each captures a different part of what it means for an interaction to remain useful.

01

What changed?

Track the state that matters to the scenario: goals, shared context, relationship, world, or user engagement.

STATE
02

What happened next?

Describe the transition as progress, maintenance, degradation, or a meaningful change in direction.

EVENT
03

Which capability was needed?

Record the demand at the point of difficulty, from basic instruction following to sustained adaptation.

CAPABILITY
04

Should the exchange continue?

Make stopping conditions visible, including completion, a safety boundary, disengagement, or exhausted patience.

04 THE LIMITS

More structure does not remove judgment.

A detailed trace can create a false sense of precision if labels are treated as ground truth. Reviewers still need clear definitions, disagreement checks, and access to the underlying conversation. A label should be an argued interpretation of evidence, not a substitute for it.

The same discipline applies to interactive demos. A fixed replay can make a method legible, but it should say that it is fixed. A transparent interface preview can validate structure, but it should not suggest that a model has produced a scientific evaluation when no evaluator is connected.

i

Keep claims proportional to the evidence.
An inspectable record improves auditability. It does not, by itself, establish validity, reliability, or generalization.

05 IN PRACTICE

Build for explanation, not just ranking.

When the unit is an interaction, the interface should keep the conversation and its diagnosis close together. Reviewers should be able to move from an aggregate pattern to a specific turn, inspect why a label was assigned, and see where the method has limits.

That is the design premise behind Interactive Evo: 76 reviewed trajectories, a four-stage evaluation frame, and a case explorer that keeps evidence available for inspection. The system is a research preview, not a claim that every interaction can be reduced to one definitive score.
